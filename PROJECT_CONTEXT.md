## 1. Что такое Push Stars

Мобильная платформа для PvP-дуэлей в калистенике (iOS + Android). Компьютерное зрение (MediaPipe) считает повторения и судит технику локально на телефоне. Победители получают ресурсы для прокачки 3D-аватара. Нет живого видео — только координаты скелета передаются через сеть и рендерятся как 3D-аватар. Это решает модерацию, приватность и нагрузку на сеть.

**Позиционирование в App Store:** категория "Health & Fitness", не "Games" — для органического трафика, доверия пользователей и B2B-привлекательности.

## 2. MVP — минимальный продукт

### Режимы
- **PvP Дуэль** — два игрока онлайн, 60 секунд, отжимания
- **Ghost Mode** — соревнование с записью скелета реального игрока; решает проблему пустого матчмейкинга на старте

### Упражнения MVP
- Отжимания (push-ups) — единственное на запуск

### Навигация — 3 вкладки
1. **Play** (дуэль / поиск матча)
2. **League** (рейтинг / лига)
3. **Profile** (статистика, гардероб, настройки)

**Цель:** до первой дуэли менее 30 секунд.

## 3. Экраны и UX

### Вкладка Play
- Выбор режима: PvP или Ghost Mode
- Экран ожидания матча с таймаутом 35 сек → предложение Ghost Mode или Тренировки
- Счётчик игроков онлайн
- **Экран калибровки камеры** (перед дуэлью): расстояние до телефона, освещение, угол. Live-индикатор качества отслеживания + визуальные подсказки. Если MediaPipe не видит скелет — пользователь должен понять почему.
- Экран дуэли (60 сек, счётчик репов, скелет соперника как аватар)
- **Экран результата дуэли** (победа/поражение, дельта кубков, XP, разблокировка)

### Вкладка League
- Карточка текущего ранга с прогресс-баром до следующего
- Таблица лидеров лиги; строчка игрока всегда видна и подсвечена
- Таймер до сброса сезона

### Вкладка Profile
- Фиксированный хедер: аватар, имя, серия побед, кнопка Гардероба
- Скроллируемое тело: переключатель упражнений, график повторений за неделю (сравнение с прошлой), три цифры (победы, винрейт, всего репов), история матчей с фильтрами
- Иконка настроек в углу

### Экран настроек
Обязателен для App Store. Содержит: звук, вибрация, язык, уведомления, разрешения камеры, удаление аккаунта.

### Онбординг
- Новый пользователь сначала видит только режим Тренировка
- Первая тренировка — обучающая: экран «Эталонное движение» с фазами (вниз / пауза / вверх) и real-time подсказками
- При переключении на новое упражнение (приседания и т.д.) — снова обучающая тренировка первой

## 4. Система прогресса

| Валюта | Логика |
|---|---|
| **XP (опыт)** | За каждый реп с правильной техникой. Качает аватара. |
| **Кубки (трофеи)** | +25 за победу в PvP, −15 за поражение. Меняет ранг. Ghost Mode: +12/−7 (половина). |
| **Ранг (лига)** | Bronze → Silver → Gold → Diamond. Определяется количеством кубков. |
| **Стрик** | Счётчик текущей серии побед. Мотивирует ежедневный возврат. |

**Ghost Mode даёт кубки в 2 раза меньше** — потому что ты побеждаешь себя прошлого, а не живого соперника.

## 5. Технический стек

| Слой | Технология | Версия / детали |
|---|---|---|
| Движок | Unity | Personal, iOS + Android |
| CV (компьютерное зрение) | MediaPipe | homuler plugin, 33 точки тела, локально на устройстве |
| Синхронизация дуэли | Photon PUN2 | UDP, ~50ms latency, ~3 KB/s на игрока |
| Аватары | Genies SDK | 3.8.5, Unity Asset Store, бесплатный |
| Backend | Firebase | Auth, Firestore, RTDB, Storage, Cloud Functions, FCM, Crashlytics, Analytics |
| IAP / монетизация | RevenueCat | — |
| Кастомные скины | Cinema 4D → FBX → Genies авториггинг | Разработчик — 3D-специалист |

**Почему Photon, а не Agora:** Agora Data Streams ограничены 6 KB/s — недостаточно для сырых данных скелета. Photon PUN2 — прямой UDP peer-to-peer, ~3 KB/s на игрока, задержка ~50ms.

**Почему Firebase, а не Supabase:** Realtime Database лучше для матчмейкинг-очереди с низкой задержкой; FCM нативно интегрирован; Crashlytics + Analytics в одном SDK.

**Почему Genies, а не Ready Player Me:** RPM закрыт (Netflix, январь 2026). Genies — бесплатный, Unity Asset Store, iOS + Android.

**Скелет:** только 17 верхних суставов (не все 33), int16-квантизация, 30 fps для live PvP, 15 fps для Ghost Mode хранилища (~63 KB на 60-секундную сессию).

## 6. Firebase — архитектура (краткая выжимка)

Полная документация: `firebase-architecture-v2.md`

### Ключевые константы
```javascript
MAX_REPS_PER_MATCH = 65      // физический максимум отжиманий за 60 сек
MATCH_DURATION_SEC = 60
TROPHY_WIN = 25
TROPHY_LOSS = 15
MATCHMAKING_TIMEOUT_SEC = 35
GHOST_MAX_SESSIONS = 5       // макс. ghost-сессий на игрока
GHOST_TTL_DAYS = 30
GHOST_MAX_FILE_BYTES = 204800 // 200 KB
LEADERBOARD_CACHE_SEC = 60
```

### Firestore — главные коллекции
- `users/{uid}` — профиль игрока
- `matches/{matchId}` — история матчей; поле `playerUids: array` для array-contains запроса
- `leaderboard/{leagueId}/players/{uid}` — предрассчитанный лидерборд (обновляется Cloud Function каждые 5 мин)
- `ghost_sessions/{uid}/sessions/{sessionId}` — метаданные ghost-записей
- `seasons/{seasonId}`, `leagues/{leagueId}` — конфиги сезона и лиг

### Cloud Functions
| Функция | Триггер | Статус |
|---|---|---|
| `onMatchFinished` | Photon Webhook (RoomClosed) | ✅ Код написан |
| `onGhostMatchFinished` | HTTP callable (клиент) | ✅ Код написан |
| `cleanupMatchmaking` | Scheduled каждую минуту | ✅ Код написан |
| `syncOfflineXp` | HTTP callable (клиент) | ✅ Код написан |
| `matchPlayers` | RTDB trigger | ⚠️ Описана, кода нет |
| `recalculateLeaderboard` | Scheduled каждые 5 мин | ⚠️ Описана, кода нет |
| `updateLeaderboardEntry` | Вызывается из onMatchFinished | ⚠️ Описана, кода нет |
| `onUserDeleted` | Auth trigger | ⚠️ Описана, кода нет |
| `sendMatchResultPush` | Вызывается из onMatchFinished | ⚠️ Описана, кода нет |

### Критические архитектурные решения
- **`onMatchFinished` вызывает Photon сервер через Webhook**, не клиент — единственный надёжный механизм, клиент не может подделать результат
- **Security Rules:** клиент пишет только `fcmToken`, `displayName`, `offlineXpPending`, `offlineXpSyncToken` через `affectedKeys().hasOnly()`
- **Лидерборд:** предрассчитывается каждые 5 мин → экономия reads ~50x
- **Ghost поиск соперника:** `trophiesAtRecord ± 100` для матчинга по уровню
- **`syncOfflineXp`:** идемпотентен через `offlineXpSyncToken` (UUID, генерируется клиентом)
- **Индекс Firestore:** `matches` → составной `playerUids ARRAY, createdAt DESC`

## 7. Unity — текущее состояние

> ⚠️ Описание ProfileScene с рабочим Genies-аватаром ниже относилось к **раннему прототипу**, а
> не к текущему репозиторию. В этом проекте на момент фазы 03: **нет** ProfileScene, **нет**
> Genies SDK (его нет в `Packages/manifest.json`), **нет** кода аватара. Это чистый скелет.
> Опыт прототипа (двухслойный Animator, Render Texture с прозрачным фоном) переиспользуем как
> образец, когда будем подключать Genies в фазе 10.

### Что сделано (этот репозиторий)
- Фазы 00–03: Core/ServiceLocator, AppBootstrap (Boot→Main), дизайн-система (тема, Rubik,
  префабы), демо-экраны.
- **Главный VS-экран** (`Main.unity`, Duel-вкладка): собран `Tools → Push Stars → Build Main
  VS Screen`. 3D-персонаж в центре через `CharacterStage` (камера → RenderTexture → RawImage,
  прозрачный фон, слой `Character`), пока placeholder-гуманоид из примитивов. В фазе 10
  `CharacterStage.SetAvatar(genies)` подменит модель — композиция не меняется.

### Прежний прототип (справочно, не в этом репо)
- **ProfileScene:** Genies-аватар + idle (Mixamo Breathing Idle) через двухслойный Animator
  (`Base Layer` + `MixamoBody` с `BodyOnlyMask`). Прозрачный фон через Render Texture
  (`Background Type: Uninitialized`, формат `R8G8B8A8_UNORM`). Character Controller отключён.

### Что не начато (нет кода, нет документации)
- MediaPipe интеграция (homuler plugin)
- Алгоритм счёта репов
- Экран калибровки камеры
- Экран дуэли
- Матчмейкинг UI
- Экран результата
- Онбординг
- Ghost Mode воспроизведение на клиенте
- Навигация (3 вкладки)

### Нужен Unity Architecture Document
Отдельный документ по Unity-стороне (MediaPipe, rep-counting, сцены, калибровка) — **не написан**. Без него агент не может полноценно работать с Unity-кодом.

## 10. Функции, критичные для запуска (не MVP, но нужны)

| Функция | Почему важно |
|---|---|
| **Оффлайн-режим тренировки** | Без интернета приложение бесполезно. XP локально → синхронизация при подключении. Критично для retention. |
| **Обработка разрыва соединения** | Если игрок вышел: победа оставшемуся, возврат кубков, повторное подключение за 10 сек. |
| **Push-уведомления** | Стрик под угрозой, вызов на дуэль, сезон заканчивается, новый ранг. Без этого retention рухнет на Day 3. FCM + APNs обязательно. |
| **Deep link «Вызвать друга»** | Прямой вызов друга — главный канал виральности на старте. |
| **Экран настроек** | Обязателен для App Store (звук, вибрация, язык, уведомления, разрешения камеры, удаление аккаунта). |

## 12. Ключевые принципы работы с агентом

- Cursor пишет ~80% кода (C# скрипты, Cloud Functions, конфиги)
- Разработчик выполняет ~20% — механические действия в Unity Editor (drag & drop, создание сцен, Play)
- Cursor **не может** взаимодействовать с Unity Editor GUI — только даёт пошаговые инструкции что нажать
- Все архитектурные решения принимаются **до** передачи задачи агенту — не во время
- Документы — главный артефакт передачи контекста агенту
