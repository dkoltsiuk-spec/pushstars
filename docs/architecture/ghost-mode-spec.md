# Ghost Mode — спецификация (Push Stars MVP)

## Продуктовое определение

**Ghost Mode** — дуэль игрока против **своей же лучшей записи** по выбранному упражнению (MVP: отжимания). Живой оппонент не нужен; это снимает «пустой» матчмейкинг на старте и даёт постоянный соперник.

**Награды:** трофеи начисляются **вдвое меньше**, чем в PvP победа/поражение (см. [constants.md](constants.md): `TROPHY_GHOST_WIN`, `TROPHY_GHOST_LOSS`). XP начисляется по тем же правилам качества повторов, что и в тренировке/дуэли (уточнение баланса в фазе backend).

## Отличия от старого черновика firebase-architecture-v2

| Было | Стало |
|------|-------|
| Поиск чужих публичных `ghost_sessions` по `trophiesAtRecord` | Не используем чужих игроков в MVP Ghost |
| Воспроизведение по `PhotonNetwork.ServerTimestamp` | Photon **не используется** в Ghost; таймер локальный (`Time.realtimeSinceStartup` или `Stopwatch`), синхронизированный с UI таймера 60 с |
| `onGhostMatchFinished` только XP | Callable обновляет **трофеи ±ghost**, **XP**, **totalReps**, пишет документ `matches` с `mode: "ghost"` |

## Данные

### Firebase Storage

- Путь: `ghost/{uid}/{exerciseId}/best.bin` (или фиксированный `ghost/{uid}/best.bin` если MVP только pushups).
- Запись файла: через **Cloud Function** после валидации размера (`GHOST_MAX_FILE_BYTES`) или через подписанный URL — решение в фазе 12 (предпочтительно CF для античита метаданных).

### Firestore — метаданные лучшей записи

Рекомендуемая схема (один документ на упражнение):

```
ghost_sessions/{uid}/best_pushups   // document id = стабильный id упражнения
  exercise: "pushups"
  storagePath: string
  bestRepsAtRecord: number          // репы в той сессии, которая считалась «лучшей»
  recordedAt: timestamp
  durationSec: number                // обычно 60
```

Для MVP достаточно **одного** упражнения — можно использовать фиксированный doc id `pushups`.

### Матч Ghost в `matches/{matchId}`

Чтобы история в профиле была единообразной:

- `mode: "ghost"`
- `playerAUid`: текущий пользователь
- `playerBUid`: тот же uid **или** специальное значение `ghost:self` (выбрать один вариант и не смешивать)
- `playerUids`: `[uid]` **или** `[uid, uid]` — Firestore `array-contains` должен находить матч; предпочтительно **`playerUids: [uid]`** и правило безопасности «читать если свой uid в массиве»
- `winnerUid`, `playerAReps`, «репы ghost» как `playerBReps` (число из записи, воспроизведённое как счётчик за 60 с)

**Важно:** правила Firestore для `matches` сейчас требуют `request.auth.uid in resource.data.playerUids`. Если второй элемент — плейсхолдер, он всё равно должен быть валидным и не ломать запросы.

## Поток клиента

1. Пользователь выбирает Ghost на экране дуэли (если есть `best.bin` и пройден минимальный онбординг).
2. Клиент загружает `best.bin`, парсит кадры (формат — см. [firebase-architecture-v2.md](firebase-architecture-v2.md), раздел «Загрузка и воспроизведение»).
3. Старт матча: локальный countdown → 60 с активной фазы.
4. Локально: MediaPipe считает репы живого игрока; параллельно по времени с начала матча воспроизводится скелет ghost на аватаре (Genies).
5. Конец: экран результата сравнивает живые репы vs «ghost reps» (из записи: либо заранее сохранённый счётчик, либо пересчёт из ключевых событий в записи — упростить для MVP: хранить `ghostRepoCount` в метаданных сессии).
6. Клиент вызывает **`onGhostMatchFinished`** с финальными репами, идентификатором ghost-документа и nonce для идемпотентности (опционально).

## Сервер — `onGhostMatchFinished` (callable)

Обязательные проверки:

- Аутентификация
- `reps <= MAX_REPS_PER_MATCH`
- Сравнение с сохранённым `bestRepsAtRecord` / контроль подделки (минимум: не принимать репы выше лимита; продвинутое: сверка с загруженным файлом — позже)
- Идемпотентность: `ghostMatchNonce` или reuse паттерна `offlineXpSyncToken`

Обновления:

- Трофеи: победа `+TROPHY_GHOST_WIN`, поражение `-TROPHY_GHOST_LOSS`
- XP, totalReps, lastMatchAt, winStreak (если победа над своим рекордом трактуется как win — **продуктово**: победа если текущие репы > ghost reps)
- Запись в `matches`
- Пересчёт `winRate` (как после PvP) — той же вспомогательной функцией, что и для `onMatchFinished`
- Если новый результат лучше предыдущего best — клиент после успеха инициирует обновление записи (или CF делает это в том же вызове при передаче нового файла — по решению фазы 12)

## UX

- Если **нет** сохранённой лучшей записи — Ghost недоступен; показать CTA «Сделай тренировку» / «Побей свой рекорд в тренировке».
- Таймаут матчмейкинга PvP (30 с): предложить Ghost как альтернативу.

## Оффлайн

Ghost против записи требует загрузки файла из Storage → **нужен интернет**. Тренировка без ранга остаётся оффлайн-capable (фаза 09).
