# Онлайн-лига

Согласованная политика: общий рейтинг каждой из четырёх лиг, календарный месяц по UTC, без сброса кубков. Участник появляется в новом сезоне при открытии лиги или завершении рейтингового боя. Неактивные аккаунты автоматически в новый сезон не копируются. Число участников не ограничено размером группы.

## Источник данных

`users/{uid}.trophies` — серверные кубки. `seasons/YYYY-MM/players/{uid}` — таблица месяца с именем, кубками, лигой, ключом сортировки и лучшей подтверждённой записью повторений. Старые локальные кубки не импортируются. `LocalProfile`, XP, инвентарь и история устройства остаются отдельным локальным состоянием; облачный рейтинг не является полной синхронизацией аккаунта.

Пороги: Bronze 0–399, Silver 400–799, Gold 800–1199, Diamond 1200+. Повышение и понижение происходят по текущим кубкам. При равных кубках UID задаёт стабильный порядок без случайной перестановки мест.

## Рейтинговый бой

Вход через кнопку в League: сначала `CALIBRATE RANK`, затем `PLAY RANKED`. Обычные локальные режимы остаются локальными и подписаны на экране наград.

1. `beginRankedMatch` фиксирует одну сессию на UID. Повтор запроса с тем же ID безопасен. До начала сессия действует 15 минут.
2. Первый онлайн-замер задаёт 0/60/150/280/420 кубков для порогов 0/10/20/35/50 повторов. Повторное начальное начисление запрещено.
3. Для Ghost сервер выбирает запись другого участника той же лиги из первых 50 мест с ближайшим числом повторов. Если записей других участников нет, используется собственная лучшая серверная запись. Это асинхронная дуэль; второй участник не теряет кубки за бой против его записи.
4. `startRankedMatch` запускает серверные часы перед живой частью. После старта результат должен поступить за 120 секунд. Рейтинговая дуэль длится 60 секунд и не ставится на паузу. Замер можно закончить раньше.
5. `finishRankedMatch` принимает временные отметки повторений, проверяет порядок, длительность, интервал не менее 0.4 секунды и максимум 65 повторов. Клиент не присылает победу, дельту или итоговый баланс. Сервер считает исход по замороженному сопернику.
6. Ghost: +12/−7, ничья 0, нижняя граница 0. Победа даёт ещё `max(0, rankedStreak−1)` за последовательные UTC-дни с ненулевым рейтинговым результатом. Локальные тренировки не продлевают серверную серию.
7. Профиль, строка сезона, история и квитанция записываются одной транзакцией. Повторная отправка возвращает ту же квитанцию. Прерванная начатая дуэль после истечения срока получает поражение. Незавершённый замер кубков не даёт.

Клиент сохраняет исходящую квитанцию до сетевого запроса в `ranked-results-v1.json`, привязывает её к UID и повторяет отправку при открытии лиги/старте следующего рейтингового боя. Окончательно отклонённые запросы сохраняются отдельно в `ranked-rejected-v1.jsonl`. Результат без ответа не выдаётся за подтверждённые кубки. После 120 секунд неподтверждённая дуэль считается прерванной, даже если устройство сохранило повторы.

## Таблица и сезоны

`getLeagueStandings` возвращает 25 участников, курсор продолжения, число участников, собственную строку и точное место. Строки и счётчики читаются в одной транзакции. Клиент обновляет таблицу раз в 60 секунд, закрепляет собственную строку над навигацией, позволяет загрузить следующие страницы и прошлые месяцы. При потере сети сохранённая таблица помечается OFFLINE.

Сервер обновляет кубки сразу, без периодического переписывания всей таблицы. `rotateLeagueSeason` каждые 5 минут создаёт текущий месяц, закрывает старые метаданные и обрабатывает до 100 истёкших сессий за запуск. Серверные записи всегда выбирают сезон по UTC, поэтому задержка планировщика не продлевает старый месяц. Прошлые таблицы сохраняются; исключение — удаление данных аккаунта. Призы за сезон пока не предусмотрены.

## Развёртывание

2026-09-30: после явного разрешения пользователя Firebase CLI завершил публикацию в `push-stars-d620e` сообщением `Deploy complete!`. Опубликованы шесть новых функций лиги, обновлены три обработчика профиля/аккаунтов, правила и индексы Firestore. Новые callable-функции и планировщик работают в `us-central1`; существующие Auth-триггеры сохранены в `us-east1`. Это подтверждение развёртывания, а не игрового end-to-end теста. Изменения C# находятся в Unity-проекте; мобильная сборка в этой задаче не выпускалась.

Нужны новые функции `getLeagueStandings`, `beginRankedMatch`, `startRankedMatch`, `finishRankedMatch`, `cancelRankedMatch`, `rotateLeagueSeason`, обновлённые `ensureProfile`, `onUserCreated`, `onUserDeleted`, правила и индексы Firestore. Регион — существующий `us-central1`. Планировщик требует разрешённый Cloud Scheduler/PubSub и биллинг проекта. Индекс `players(league, standing)` нужен до первого запроса; `rankedSessions(state, expiresAtMs)` — для очистки истёкших боёв.

## Границы реализации

Сервер владеет кубками и исходом, но физическое выполнение упражнения всё ещё подтверждает клиентский CV. Проверка временных отметок не заменяет серверную проверку видео или аттестацию устройства. Перед соревновательным релизом нужны проверки на двух устройствах, обрыва сети, повторной отправки, перехода месяца и защита от модифицированного клиента.

Синхронного PvP-транспорта и серверного источника результатов Photon здесь нет. Настоящие участники соревнуются в общей таблице и через записи Ghost. Правила PvP +25/−15 остаются заготовкой для будущего доверенного обработчика PvP; публичного API для самостоятельного заявления победы нет.

В этой задаче выполнены проверки синтаксиса JavaScript и компиляция Unity. Автоматические тесты и игровые проверки на устройствах не запускались.
