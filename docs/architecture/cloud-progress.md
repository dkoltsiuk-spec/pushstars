# Облачный прогресс аккаунта

Прогресс игрока, вошедшего через Apple, Google или почту, хранится в облаке и восстанавливается после переустановки и на втором телефоне. Гость играет только с сохранением на устройстве: его анонимный UID пропадает вместе с приложением, поэтому гость в облако ничего не пишет.

## Что входит в прогресс

Инвентаризация локальных хранилищ (2026-10-21):

| Хранилище | Где | В облаке |
|---|---|---|
| `CaseRewards` — гемы, Аура и пик, герои и карточки, арены, эмоуты, кейсы, суточная квота кейсов, все квитанции наград | PlayerPrefs `rewards.case_ledger.v1` | да, JSON сохранения как есть |
| `LocalProfile` — XP (и уровень), кубки устройства, победы/поражения, серия побед, огонёк (дни подряд), история тренировок (из неё же дневная цель) | `workouts_v1.json` | да, JSON сохранения как есть |
| Лестница боссов | PlayerPrefs `boss_progress` | да |
| Онбординг: интро, замер, его повторы, «потом» | PlayerPrefs `onboarding.*` | да |
| Имя, аватар, страна профиля | PlayerPrefs `profile.identity.{uid}.*` | да (ключ с `{uid}`) |
| Выбранные герой, пол, арена; старые `arena.owned.*` | PlayerPrefs | да |
| Лучший подход (гост) | `ghost_pushups.json` | да, отдельным документом |
| Звук, вибро, язык, напоминания, раскладки, «просмотрено» в магазине/лиге/карте | PlayerPrefs | нет — настройки телефона |
| Очередь рейтинговых результатов | `ranked-results-v1.json` | нет — уже привязана к UID и уходит на сервер сама |

Ачивок и заморозок огонька в коде пока нет; когда появятся — добавить их хранилище в `ProgressStore`.

## Firestore

```
users/{uid}/progress/state   rev, schema, snapshot (gzip+base64), summary, updatedAtMs, updatedAt
users/{uid}/progress/ghost   data (gzip+base64), reps, updatedAtMs
```

`snapshot` — `ProgressSnapshot` клиента: `ledger` и `workouts` лежат строками ровно в том виде, в каком их пишет устройство (тики UTC не теряют точность, восстановление идёт через те же проверки и миграции, что и обычная загрузка). `summary` сервер считает сам — для проверок и для консоли.

Правила: документ читает только владелец, прямая запись запрещена. Пишут только функции:

- `loadProgress` → `{exists, rev, snapshot, hasGhost, ghost}`;
- `saveProgress {baseRev, snapshot, sendGhost, ghost}` → `{rev}`. Сохраняет только поверх `baseRev`, иначе `aborted`. Гость получает `failed-precondition`.

`onUserDeleted` удаляет оба документа.

## Проверка на сервере (`functions/src/progressRules.js`)

Экономика зарабатывается на телефоне, сервер не может её переиграть. Он не даёт облачной копии раздуваться легче, чем при игре:

1. **Структура.** Оба сохранения парсятся, числа — целые неотрицательные, списки ограничены, Аура не больше пика, размер документа < 1 МиБ, распаковка ограничена 8 МБ.
2. **Доказательства.** Каждый итог ограничен тренировками, которые его дали: повторы тренировки — её временем (≤ 65 за минутный бой), XP — повторами, Аура — числом тренировок, гемы — кейсами и наградами карты, кейсы — тренировками, кубки — дельтами истории, боссы — боями.
3. **Темп.** Число тренировок, через которое ограничено всё остальное, не растёт быстрее одной в 45 секунд по серверным часам (плюс запас 20).

Лига копию не читает: кубки лиги по-прежнему считает только сервер (`league.js`). Когда появятся покупки гемов за деньги, их нужно начислять по проверенным чекам магазина, иначе правило гемов отклонит такие сохранения.

## Клиент

- `Core/CloudSave/ProgressStore` собирает и применяет снимок; `ProgressEvents.Changed` поднимается после каждого сохранения хранилищ прогресса.
- `Core/CloudSave/CloudSaveRules` — чистая таблица решений (EditMode-тесты).
- `Firebase/CloudProgressSync` — загрузка/выгрузка, метаданные `cloud.*` в PlayerPrefs: чей прогресс на телефоне (`owner_uid`, `owner_anonymous`), ревизия, хэши последней выгрузки.

Выгрузка: через 8 с после последнего изменения, сразу при уходе приложения в фон, повтор через 45 с без сети; если хэш снимка совпадает с выгруженным — ничего не отправляется. Гост уходит, только когда изменился.

### Чей прогресс на телефоне

Решается при старте сессии Firebase (Boot или Settings), после привязки и после смены аккаунта:

| Ситуация | Решение |
|---|---|
| Гость привязал Apple/Google/почту (UID тот же) | локальный прогресс становится прогрессом аккаунта, первая выгрузка |
| «Сменить аккаунт?» → у аккаунта есть облачная копия | берётся облако, прогресс гостя заменяется |
| «Сменить аккаунт?» → у аккаунта копии нет | прогресс гостя переходит в аккаунт; прогресс другого *аккаунта* — никогда (иначе кошелёк копируется во второй аккаунт) |
| Тот же аккаунт, другой телефон ушёл вперёд, здесь ничего не менялось | берётся облако |
| Оба телефона изменили один аккаунт | побеждает более продвинутая копия: пик Ауры, затем XP, затем число тренировок; поля не смешиваются, ничего не выплачивается дважды |
| Переустановка, сессия восстановилась (iOS хранит её в связке ключей) | облако, если оно продвинутее свежего сохранения |
| Выход из аккаунта | сначала выгрузка (без сети выход не выполняется, текст об этом), затем телефон начинает новым гостем: интро не показывается снова, замер предлагается с главного экрана |
| Удаление аккаунта | облако удаляет `onUserDeleted`, телефон начинает новым гостем |

Подменить сохранение можно только на Boot (до маршрутизации) или на Main, который после этого перезагружается; во время боя восстановление ждёт следующего Main. Привязанный телефон при запуске ждёт облако до 4 с (`AppBootstrap._cloudRestoreWaitSec`), без сети открывается с локальным сохранением.

## Проверка

- Unity EditMode: `Assets/_Project/Tests/EditMode` — таблица решений, ранжирование, сериализация и транспорт снимка, восстановление кошелька и истории через настоящие леджеры, ключи. `ProgressSnapshotTests` пишет golden-файлы `functions/test/fixtures` при `PUSHSTARS_WRITE_FIXTURES=1`. Тесты не трогают PlayerPrefs и файлы игрока.
- Node: `npm test` в `functions` — правила проверки на снимке, упакованном Unity.
- Эмуляторы: `npm run test:emulator` (проект `demo-pushstars`, Auth + Firestore + Functions) — гость → привязка Google → выгрузка; переустановка и второй телефон входят тем же Google и получают тот же снимок и гост; гонка двух телефонов даёт `aborted`; гость, чужой аккаунт, прямая запись и поддельный кошелёк отклоняются.
- Не проверено на устройствах: нативные Apple/Google, поведение в фоне iOS/Android, восстановление сессии из связки ключей iOS.
