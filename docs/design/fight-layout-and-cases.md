# Отдельные сцены боя, наград и кейсов

Все семь экранов — обычные `.unity`-сцены в `Assets/_Project/Scenes`. Их интерфейс сохранён в файлах сцены и виден без Play Mode.

| Сцена | Назначение |
|---|---|
| `FightPreparation` | Подготовка к бою |
| `Fight` | Сам бой |
| `FightResults` | Результаты боя |
| `RewardSummary` | Анимированный показ начисленных XP, кубков и ауры |
| `CaseAward` | Сообщение о получении кейса; открыть сейчас или оставить на потом |
| `CaseOpening` | Три попытки улучшения и открытие выбранного кейса |
| `CaseReward` | Получение приза из выбранного открытого кейса |

## Редактирование в Unity

1. Останови Play Mode и открой нужную сцену двойным кликом в папке `Assets/_Project/Scenes`.
2. Выбери элемент в **Hierarchy** или в окне **Tools → Push Stars → Fight Layout Editor**. Теперь это окно открывает настоящие сцены и помогает выбирать их элементы.
3. Двигай элемент инструментом **Rect (T)** в **Scene**, меняй размер, текст, цвет или другие свойства в **Inspector**.
4. Сохраняй обычным **Ctrl+S**. Изменения остаются в сцене и попадают в сборку.

Анимированные картинки и счётчики расположены внутри отдельных групп. Для перемещения всей награды двигай группу, для изменения картинки или подписи — соответствующий дочерний объект. Анимации учитывают сохранённые масштаб и поворот.

Прямой запуск любой из этих сцен в редакторе использует демонстрационные данные и не выдаёт настоящие награды. Изменения объектов, сделанные во время Play Mode, как обычно в Unity, не сохраняются в сцену. Для постоянного редактирования используй Scene вне Play Mode.

Старое сохранение через **«Сохранить для сборки»** и `ScreenLayouts.asset` больше не требуется. В этих сценах источником расположения стали их `RectTransform`; прежние персональные макеты в PlayerPrefs не перекрывают правки сцены. Кнопка **«ДВИГАТЬ UI»** в новых сценах отключена.

## Переходы настраиваются отдельно

Общей обязательной цепочки из семи экранов нет. Каждый экран выбирает следующее действие через свой компонент в **Inspector**:

| Компонент | Настраиваемые направления |
|---|---|
| `PreparationScreen` | `Ready Destination` — куда перейти после готовности |
| `ResultsScenePresenter` | `Continue Destination` — куда перейти с результатов |
| `RewardScreen` | `Home Destination`, `Award Destination`, `Open Destination`, `Prize Destination` — направления соответствующих действий |

Значения выбираются из списка `FightScreen`. `Home` возвращает в сцену, откуда был открыт данный сценарий; обычно это `Main`. После изменения направления сохрани сцену.

Начисление XP, кубков и кейсов выполняется игровой логикой отдельно от отображения. Открытие `RewardSummary` или `CaseAward` само по себе ничего не выдаёт. В обычном бою результаты могут открыть сводку начислений; из неё можно сразу уйти домой. Кнопка просмотра полученного кейса появляется только если именно этот бой выдал новый кейс. Наличие старых неоткрытых кейсов не запускает их автоматически.

На `CaseAward` игрок выбирает **открыть сейчас** или **позже**. На `CaseReward` получение приза возвращает домой. Следующий кейс из очереди автоматически не открывается. Незабранные кейсы доступны через кнопку **КЕЙСЫ** на главной, в том числе после перезапуска.

Для входа из других частей игры используется `FightScreenNavigation`:

```csharp
// Показать уже рассчитанную сводку без привязки к выдаче кейса.
FightScreenNavigation.ShowSummary(summary, returnScene: "Main");

// Сообщить о кейсе, уже выданном другой системой.
FightScreenNavigation.ShowCaseAward(caseId, returnScene: "Main");

// Открыть конкретный сохранённый кейс; открытый кейс сразу покажет свой приз.
FightScreenNavigation.OpenCase(caseId, returnScene: "Main");
```

`ShowCaseAward` и `OpenCase` возвращают `false`, если указанного незабранного кейса нет. Данные между сценами передаются отдельно от UI; состояние кейса и приза сохраняется в инвентаре.

## Когда выдаётся кейс

По умолчанию за завершённую тренировку с хотя бы одним засчитанным повтором можно получить **один кейс за календарный день UTC**, а не за каждый бой. Открытие или получение приза не обновляет дневной лимит. Повторный callback того же боя не выдаёт кейс повторно, в том числе на следующий день.

Настройки находятся в `Assets/_Project/Resources/CaseRewardPolicy.asset`:

- `Daily Workout Case Limit` — число кейсов за день; `0` отключает этот источник.
- `Minimum Workout Reps` — минимальное число повторов в завершённой тренировке.

Выдача за другую причину отделена от дневной награды за тренировку:

```csharp
// Уникальный стабильный ID события защищает от повторной выдачи.
string receiptId = "quest:weekly-2026-09-14:player-id";
if (CaseRewards.TryGrantCase(receiptId))
    FightScreenNavigation.ShowCaseAward(receiptId);
```

`TryGrantCase` кладёт кейс в инвентарь и не переключает сцену. Показ сообщения необязателен. Эта явная выдача не расходует лимит тренировочных кейсов; условия квеста, акции или другого источника проверяет вызывающая система.

Календарный день определяется по часам устройства в UTC. Сейчас это локальная офлайн-политика, а не серверная проверка времени. Старые инвентари и баланс сохраняются при переходе на новую версию; для них дневной учёт начинается со следующей новой тренировки.

## Улучшение и получение приза

Три тапа дают три попытки повысить редкость. Неудачный тап также расходует попытку. После трёх попыток следующий тап открывает кейс.

| Редкость | Картинка | Шанс повышения за тап | Кристаллы |
|---|---|---|---|
| Обычный | Чёрный кейс | 45% | 10–25 |
| Редкий | Синий кейс | 30% | 30–60 |
| Эпический | Золотой кейс | 15% | 80–140 |
| Легендарный | Фиолетовый кейс | Максимальная редкость | 180–300 |

Числа настраиваются в `Assets/_Project/Scripts/Core/Economy/CaseRewards.cs`. Каждый принятый тап и открытый приз сохраняются сразу: повторный вход не перебрасывает редкость и награду. Получение приза одной записью увеличивает баланс кристаллов и убирает кейс из очереди. Повторное нажатие не начисляет приз ещё раз.

Кристаллы, инвентарь, выданные события и дневной лимит хранятся локально в PlayerPrefs под прежним ключом `rewards.case_ledger.v1`. Серверная экономика в эту реализацию не добавлялась.

Исходные PNG из «Загрузок» находятся в `Assets/_Project/Resources/Rewards`: `CaseCommon`, `CaseRare`, `CaseEpic`, `CaseLegendary`, `Gems`. Для замены сохрани имя и `.meta` соответствующего PNG.

## Проверки

- `PushStars.Editor.CaseRewardsRegression.Run` — дневной лимит, UTC, повторные события, независимая выдача, миграция инвентаря, улучшение, получение и ошибки записи; использует отдельные сохранения в памяти.
- `PushStars.Editor.FightFlowRegression.Run` — семь файлов сцен, видимость UI вне Play Mode, ссылки, редактируемые элементы и сохранение изменённых координат через закрытие и повторное открытие копии сцены.
- `PushStars.Editor.ScreenLayoutRegression.Run` — сохранение геометрии, отмена, сброс и защита от некорректных данных в прежнем механизме макетов.
- `PushStars.Editor.FightScreensPlayValidation.Run` — запускает семь настоящих сцен в Play Mode, снимает их в `Logs/fight-screens`, проверяет уход домой без открытия кейса, три улучшения, переход к призу и получение без автоматического открытия следующего кейса. Сравнивает сохранённые награды, XP, профиль и макеты до и после предпросмотра.

Последний метод предназначен для отдельного batch-запуска Unity с графикой и без `-quit`: он сам завершает процесс по окончании проверки.
