# Запись тестового бота на телефоне

## Сборка и доступ

Нужна новая сборка приложения: C#-изменения не приезжают с обновлением сцен/картинок OTA.
В Unity включить **Development Build**. Для существующего CI-метода
`PushStars.Editor.BuildScript.BuildiOS` добавить аргумент **`-botRecordingTest`**
к команде Unity на Mac; это включает Development Build только для этого запуска.
Обычная сборка остаётся без кнопки. Установка/подпись iOS остаётся в существующем
Mac/CI-процессе проекта.

На главном экране появится **BOT LAB**. Не нужно пересобирать сцены или вручную
добавлять компоненты. Для доступа в обычной сборке оператор проекта может создать
закрытый документ Firestore `botRecorderAccess/{Firebase UID}` с `enabled: true`.
Кнопка **COPY ACCOUNT UID** копирует UID из тестовой сборки. Клиент не может сам
создать разрешение; существующие правила Firestore закрывают эти коллекции.

## Проверка на устройстве

1. Открыть **BOT LAB → RECORD A NEW BOT**. Пройти экран подготовки, занять планку
   и дождаться отсчёта. Сейчас тест записывает один стандартный 60-секундный бой.
2. Сделать несколько быстрых повторений, заметную паузу 8–10 секунд, затем несколько
   медленных. При желании добавить хлопок. Дождаться конца боя.
3. Сначала появляется **SAVED ON DEVICE**, после подтверждённой записи файла и
   метаданных сервером — **BOT SAVED IN CLOUD**. Карточка содержит ID и число повторений.
4. **FIGHT LOCAL RECORDING** запускает соперника из файла телефона.
   **LOAD CLOUD COPY & FIGHT** заново скачивает запись с сервера и запускает именно её.
5. Проверить, что счёт меняется в исходные моменты, пауза остаётся паузой, а движения
   и хлопки повторяются. Длительность своей подготовки может отличаться: запись боя
   всегда стартует вместе с новым отсчётом. После теста виден счёт «ты : бот».

Запись и тестовый бой не меняют XP, кубки, кейсы, лучший личный рекорд и рейтинг.
Прерванная запись не считается готовым ботом. Отключение интернета не удаляет уже
сохранённый файл: **RETRY CLOUD SAVE** повторяет загрузку того же ID, включая после
перезапуска приложения. Все предыдущие файлы сохраняются; панель первого теста
показывает последнюю запись. Публичный поиск не использует эти черновики.

## Формат и воспроизведение

- `GhostRecord.repTimes` — исходные секунды засчитанных повторений; значения никогда
  не распределяются заново по минуте. Один список также определяет финальный счёт.
- `motionBase64` — gzip+base64 бинарного PSR1: header `uint32 magic`, `int32 muscles=95`,
  `int32 frames`; кадр `byte phase`, `float time`, body position/rotation, root local
  position/rotation и 95 float-мышц. Все числа little endian; кадр 441 байт.
- Записывается итоговая поза аватара после CV-зеркала и коррекции движений, до камеры.
  Цель — до 30 кадров/с; фактическое время каждого кадра сохраняется. Видео не пишется.
- Три независимых времени: preparation=0, setup/countdown=1, live=2. Подготовка и
  setup ограничены первыми 60 секундами каждый; затем удерживается последний кадр.
  Бой всегда запускает собственный live-таймер без ускорения или растягивания записи.
- Существующие ghost-записи без поз продолжают работать. В них длинные интервалы
  больше не превращаются в медленные отжимания: используется приближение движения
  перед событием. Точные старые движения восстановить нельзя — нужна новая запись.
- При новом обычном локальном бое тоже записывается анимация; лучший сохранённый
  ghost получает её. Текущий онлайн-рейтинг пока передаёт только `repTimes` и сохраняет
  совместимый режим без полной анимации.

## Облако

Функции `getBotRecorderAccess`, `saveBotRecording`, `getBotRecording` развёрнуты в
`push-stars-d620e`, `us-central1`. Загружаются только приватные черновики владельца:
Storage `bot-drafts/{uid}/{id}.json`, Firestore `botDraftOwners/{uid}/recordings/{id}`.
Клиент получает их только через авторизованные функции. Публичных URL нет.
До 15 неизменяемых записей на аккаунт, до 2 MiB сжатой анимации на запись.
Квота резервируется до загрузки; сбой не меняет статус на ready, повтор использует
тот же ID. SHA-256 проверяет облачную копию. Имена/флаг/аватар/трофеи хранятся отдельно
от временной шкалы; первый бот называется TEST BOT и берёт внешний вид и флаг игрока.

## Проверки

- `node --test functions/test/botRecordings.test.js functions/test/heartbeatPresence.test.js`
- Unity: `Tools → Push Stars → Bots → Validate Recording`, либо batchmode
  `-executeMethod PushStars.Editor.BotRecordingValidation.Run`.
- Проверяются неравномерные серии, паузы, независимые времена фаз, старые записи,
  перенос Humanoid-позы между удалёнными и повёрнутыми площадками, изоляция тестового
  запроса, облачные права владельца, повторная загрузка, сбой загрузки и целостность.
- Физическую запись с камеры, внешний вид на телефоне и подписанную сборку проверяет
  разработчик на устройстве. Эти проверки не заменяются синтетическим ботом.
