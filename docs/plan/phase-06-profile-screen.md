# Фаза 06 — Экран профиля и статистики

## Цель фазы

Реализовать вкладку **Профиль** по макету экрана 7: аватар (placeholder или Genies после фазы 10), имя, стрик, кнопка «Гардероб», переключатель упражнений (MVP только pushups disabled/enabled для будущего), график недели, три KPI (победы, винрейт, всего повторений), история матчей с фильтрами TYPE / MODE и пагинацией.

## Что НЕ делаем в этой фазе

- Полный магазин косметики (фаза 10).
- Редактор эталона движения (фаза 09).

## Предусловия

Фазы 03, 05.

## Затрагиваемые экраны

Экран 7.

## Файлы

- `Assets/_Project/Scripts/UI/Profile/ProfilePresenter.cs` (+ View)
- `Assets/_Project/Scripts/Data/MatchHistoryRepository.cs` — запрос `matches` `array-contains` + `OrderBy createdAt`
- `Assets/_Project/UI/Prefabs/Profile/` — карточки матчей W/L

Фильтры: клиентская фильтрация первой страницы или доп. поля в матче `matchType`, `gameMode` для серверного фильтра (предпочтительно поля в документе матча).

## Acceptance criteria

- [ ] История подгружает 20 документов и «load more».
- [ ] Своя строка визуально выделена (если список смешанный — для профиля только свои матчи).
- [ ] График строится из агрегата или из локальных логов + серверной сводки — определить источник в реализации (минимум: последние 7 дней из `dailyStats` подколлекции или CF aggregate позже).

## Тестирование

Staging данные: 3+ матча win/loss.
