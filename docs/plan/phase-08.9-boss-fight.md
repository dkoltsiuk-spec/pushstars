# Фаза 08.9 — Приложение на устройстве + Босс-дуэль

## Цель фазы

Превратить девайс-сборку из «CV-теста с IMGUI-худом» в **играбельное приложение**: на телефоне живут настоящие экраны (Boot → Main), а вместо невозможного пока поиска соперника появляется первый соревновательный цикл — **дуэль против скриптованного босса** с реальным CV-подсчётом отжиманий.

Две части:

1. **A. Приложение на устройстве** *(сделано вместе с этим доком)* — сборка UBA/Codemagic шипит `Boot + Main + testCV` вместо одного testCV (`BuildScript.AppScenes`); `ci/uba_prebuild.sh` пишет настоящий `GoogleService-Info.plist` из env var `GOOGLE_SERVICE_INFO_PLIST_B64` (fallback — плейсхолдер: приложение грузится без бэкенда, UI на моках). testCV остаётся скрытой дебаг-сценой.

2. **B. Босс-дуэль** — «НАЙТИ СОПЕРНИКА» ведёт в бой против пресетного босса: полный цикл поиск → бой (камера + `PushupSession`) → результат → XP. Босс — предтеча бота-пейсера из фазы 12.5: тот же слот соперника, но без Firestore и ghost-пула.

## Что НЕ делаем в этой фазе

- Трофеи за босс-дуэли (боссы не должны инфлировать трофейную экономику; трофеи вернутся с ghost/async-дуэлями, фазы 12/12.5).
- Запись матчей в Firestore `matches` (история профиля пока на моках; схема ляжет в фазе 12).
- Ghost-записи, Photon, живой матчмейкинг.
- Приседания, режим МАКС (таймер фиксированный 60 сек — как основной режим дуэли).

## Предусловия

Фазы 08/08.1 + frontal addendum (CV-стек проверен на устройстве в testCV), фаза 03 (главный экран + оверлей поиска), экономика (`Core/Economy`: XP). Часть A этой фазы (сборка).

## Поток

1. Main, панель «Дуэль» → **НАЙТИ СОПЕРНИКА** → существующий оверлей поиска (`SearchOpponentController`); кольцо крутится `BOSS_SEARCH_DELAY_SEC`, затем «СОПЕРНИК НАЙДЕН» — ник/аватар из пресета босса.
2. Переход в новую сцену `Fight.unity` (Single-загрузка: Main с CharacterStage выгружается — камера + MediaPipe и так тяжёлые).
3. Экран боя: превью фронтальной камеры на весь экран, поверх — HUD дизайн-системы: свой счётчик реп (крупно), счётчик босса, таймер, индикатор FORM, тост-фидбек отклонённых реп (`PushupSession.OnRepRejected` — «репа не засчитана: …»).
4. Стартовый гейт: подсказка «встань в планку в кадре»; `PlankArmer.OnArmed` → отсчёт 3-2-1 → старт таймера и таймлайна босса. До старта репы не считаются (`ResetSession` на старте).
5. Босс «отжимается» по таймлайну пресета — не равномерно, а порциями с паузами, чтобы читался как живой.
6. Финиш по таймеру → экран результата: победа/поражение/ничья по репам, XP по репам (как тренировка, под `DAILY_REP_XP_CAP`) + `BOSS_WIN_XP_BONUS` за победу; активный день для стрика.
7. «ПРОДОЛЖИТЬ» → возврат в Main (Boot не перепроходится: сервисы уже в `ServiceLocator`).

## Боссы

Три пресета сложности; выбор — прогрессией (победил текущего → открывается следующий; поражение — остаёшься):

| Пресет | Ник | Темп (реп/60с) | Характер таймлайна |
|--------|-----|----------------|--------------------|
| `novice` | «Новобранец» | ~15 | рваный: серии по 3–4, длинные паузы |
| `athlete` | «Атлет» | ~25 | ровные серии по 6–8, короткие паузы |
| `champion` | «Чемпион» | ~35 | почти без пауз, лёгкое замедление к концу |

## Новые константы (добавить в `constants.md`)

| Имя | Значение (предложение) | Назначение |
|-----|------------------------|-----------|
| `BOSS_SEARCH_DELAY_SEC` | `2.5` | Сколько крутится кольцо поиска до «найден» |
| `BOSS_DUEL_DURATION_SEC` | `60` | Длительность боя |
| `BOSS_WIN_XP_BONUS` | `50` | Разовый XP-бонус за победу над боссом |
| `BOSS_PROFILES` | `novice/athlete/champion` | Пресеты боссов (темп + таймлайн) |

## Затрагиваемые экраны

Главный экран (панель «Дуэль») — точка входа без изменений вёрстки. Оверлей поиска — из косметики становится state machine: searching → found(boss) → переход. Новые: экран боя, экран результата.

## Acceptance criteria

- [ ] Девайс-сборка открывается в Boot → Main; все табы (Лига/Дуэль/Профиль) и настройки живут на телефоне; без настоящего plist приложение не падает (моки).
- [ ] «НАЙТИ СОПЕРНИКА» всегда приводит к бою с боссом за ≤ `BOSS_SEARCH_DELAY_SEC` + переход.
- [ ] Бой не стартует, пока игрок не встал в планку (`PlankArmer`); после отсчёта репы считаются тем же CV-стеком, что в testCV (античит активен, отклонённые репы показываются).
- [ ] Счётчик босса идёт по таймлайну пресета; результат определяется сравнением реп на момент истечения таймера.
- [ ] XP начисляется по правилам экономики (репы под `DAILY_REP_XP_CAP` + `BOSS_WIN_XP_BONUS`), трофеи не трогаются.
- [ ] Победа открывает следующего босса; прогрессия переживает перезапуск приложения.
- [ ] Возврат в Main после боя — без повторной инициализации Firebase и без утечки камеры (`WebCamTexture`/MediaPipe останавливаются при выгрузке сцены).

## Тестирование

На устройстве: полный цикл Main → поиск → бой → результат → Main дважды подряд (проверка повторного захвата камеры). Отказ камеры/разрешения → понятная заглушка, выход в Main. Airplane-режим: цикл работает целиком (бой офлайновый), XP копится локально (синк — путём `syncOfflineXp`, фаза 11.5). В редакторе: `FightController` на `MockPoseSource` без MediaPipe.

## Связь с фазой 12.5

Босс — временный житель слота соперника. `IOpponentFeed` — тот самый шов: в 12.5 в него встают чужая ghost-запись и бот-пейсер, экран боя и результат переиспользуются как есть, а «поиск» получает реальную приоритетную лестницу (живая очередь → ghost → бот). Пресеты боссов при этом остаются как офлайн/PvE-режим.
