# Фаза 09.5 — Первый запуск: загрузка → онбординг → замер уровня → бой против себя

> Статус: **сделано** (клиент). Серверная часть — фазы 11.5 / 12 / 12.5.

## Зачем

До этой фазы приложение открывалось чёрным экраном на время инициализации Firebase, а
единственным соперником был скриптовый босс. Не было ни первого впечатления, ни ответа на
вопрос «а я вообще сильный?», ни причины возвращаться. Фаза закрывает **весь путь первого
запуска** одним куском: игрок ставит телефон, делает один подход, получает уровень — и с этого
момента у него есть постоянный соперник, своя же лучшая запись.

Это же снимает проблему ликвидности матчмейкинга ещё до Photon: соперник есть всегда, потому
что соперник — ты сам.

## Поток

```
Boot.unity            экран загрузки (вордмарк, прогресс, статус) + инициализация сервисов
   │                  AppBootstrap решает, куда идти дальше:
   ├─ интро не пройдено ────────────────► Onboarding.unity
   │                                        4 страницы, последняя кнопка →
   ├─ интро пройдено, замера нет ───────► Fight.unity (FightMode.LevelTest)
   │                                        60 сек, максимум отжиманий →
   │                                        уровень + ghost-запись → Main.unity
   └─ всё пройдено ─────────────────────► Main.unity
                                            «НАЙТИ СОПЕРНИКА» → поиск →
                                            Fight.unity (FightMode.Ghost)
```

Три режима живут в **одной сцене** `Fight.unity`. Загрузка сцены не принимает аргументов, поэтому
намерение паркуется в статике `FightRequest` перед `LoadScene`, а `FightController.Start` его
читает. Одна сцена — один HUD, один CV-стек, одно место, где чинить проблемы на устройстве.

## Ключевые решения

### Камеры на экране нет — есть персонаж

Вебкамера работает (её читает детектор поз), но её кадр никуда не выводится. Игрок видит своё
3D-тело: стейдж-камера снимает персонажа, одиноко стоящего на слое `Character`, в RenderTexture,
который растянут на весь экран под HUD. Это обещание продукта («живого видео нет никогда») и
одновременно то, что делает экран читаемым из планки: одна крупная фигура и две цифры вместо
трясущегося широкоугольного вида комнаты.

Персонаж отжимается **в такт игроку**: `PushupAvatarDriver` не ретаргетит скелет, а скрабит
`normalizedTime` канонического Mixamo-клипа CV-сигналом глубины (вариант A, стенд фазы 08.9).

Камера кадрируется **по костям**, а не по мешу: у проекта уже была история с битыми bounds
скиннед-мешей, а позиции humanoid-костей всегда честные. `FightAvatar` строит бокс по восьми
костям и плавно подводит камеру — стоящая фигура и фигура в планке требуют совершенно разных
планов, и ни один из них не пришлось подбирать руками.

### Диагностика под кнопкой

Без кадра с камеры отказ CV на устройстве невидим. IMGUI-стенд из `testCV` остался в сцене
выключенным, кнопка `•••` в углу его включает. Пять быстрых тапов по ней стирают состояние
первого запуска и перезапускают с `Boot` — иначе повторный тест онбординга на TestFlight-сборке
означает удалить и переустановить приложение.

### Запись госта — это и есть подход

Отдельного прохода записи нет. Таймстемпы репов, которые игрок выдаёт в живой фазе, **и есть**
ghost-запись: два числа не могут разойтись, потому что число одно. Подход, который бьёт
сохранённый, его заменяет — тень, с которой ты дерёшься, всегда твоя лучшая версия.

Формат — только времена репов, не скелет. Скелет нужен, чтобы отрисовать тело соперника; пока
тела соперника на экране нет, а табло спрашивает только «сколько у него было на секунде N».
Поле остаётся совместимым: скелет фазы 12 станет ещё одним полем рядом, а не заменой.

### Ноль репов — это не уровень

Ноль означает, что камера не увидела ни одного повтора, а не что игрок новичок. Флаг замера не
ставится, экран результата предлагает повторить — и «ПРОПУСТИТЬ» для тех, у кого устройство
просто не справляется. Если планка не собралась за 45 секунд, кнопка «ВЫЙТИ» становится
«ПРОПУСТИТЬ»: без этого игрок с неработающим CV никогда не доходит до экрана результата
(60 секунд не начинаются) и каждый запуск возвращается в замер.

| `Scripts/Fight/FightController.cs` | Три режима, запись таймлайна, итоги |
| `Scripts/Fight/FightResultScreen.cs` | Итог дуэли и итог замера |
| `Scripts/UI/Loading/LoadingScreen.cs` | Прогресс-бар Boot |

| `Editor/BootSceneSetup.cs` | `Build Boot Screen` |
| `Editor/OnboardingSceneSetup.cs` | `Build Onboarding` |

Пересобрать все три сцены разом: `Tools → Push Stars → Rebuild Flow Scenes` (или
`BuildScript.RebuildFlowScenes` в batch-режиме). `Main.unity` намеренно не трогается — она
собирается `MainVsScreenSetup` и несёт сцену персонажа.

## Константы

| Имя | Значение | Где |
|---|---|---|
| Пороги уровней (репы за 60 с) | 0 / 10 / 20 / 35 / 50 | `FitnessTest.Thresholds` |
| Стартовые кубки по уровню | 0 / 60 / 150 / 280 / 420 | `FitnessTest.StartingTrophies` |
| Таймаут «замер не стартовал» | 45 с | `FightController.LevelTestStuckSec` |
| Минимальное время экрана загрузки | 1.2 с | `AppBootstrap._minVisibleSec` |

Кубки за дуэль берутся из `EconomyConfig.TrophyGhost*` (12 / 7) — как и планировалось для
ghost-режима.

## Что осталось серверу

- Загрузка записи в Storage и метаданных в `ghost_sessions` (фаза 12).
- Подбор чужой записи по трофейному диапазону и боты-пейсеры (фаза 12.5).
- `onGhostMatchFinished` — сейчас кубки и XP считаются и хранятся только локально
  (`LocalProfile`, `OfflineXpBank`), вызов callable добавляется вместе с фазой 11.5.
- Зеркалирование флагов онбординга в `users/{uid}/flags`, чтобы переустановка не гнала
  игрока через замер заново.

## Тестирование на устройстве

1. Свежая установка → должен открыться экран загрузки, затем интро.
2. Пройти 4 страницы, разрешить камеру → экран боя с персонажем, без кадра камеры.
3. Встать в планку 1.5–2 м от телефона → «ДЕРЖИ ПЛАНКУ» → 3-2-1 → 60 секунд.
4. Экран результата: уровень, репы, XP, «Запись сохранена».
5. `Main` → «НАЙТИ СОПЕРНИКА» → «ТВОЯ ТЕНЬ · N» → дуэль против своего подхода.
6. Побить запись → «НОВЫЙ РЕКОРД», следующий бой уже против нового результата.
7. Пять тапов по `•••` в бою → приложение перезапускается с интро.
