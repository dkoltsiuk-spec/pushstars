# Фаза 12.5 — Асинхронные ghost-дуэли против реальных соперников + боты-пейсеры

## Цель фазы

Снять проблему **ликвидности матчмейкинга**: живой PvP (Photon, фазы 13–14) требует двух игроков в очереди в один и тот же момент в одном трофейном диапазоне — этого не будет ещё долго (мгновенная concurrency мала даже при десятках тысяч MAU). Эта фаза делает соревновательное ядро **независимым от онлайна**, переиспользуя ghost-стек фазы 12.

Расширить Ghost: вместо записи **только своей** игрок дуэлится против **чужой сохранённой ghost-записи**, выбранной из пула по своему трофейному диапазону. Ощущается как PvP, начисляет трофеи, но не требует никого онлайн.

Когда пул в диапазоне пуст (новая лига, первые дни, узкий band) — fallback на **бота-пейсера**: заранее заготовленный синтетический «темп» (медленный / средний / быстрый), воспроизводимый тем же `GhostPlayback`. Игрок не должен отличать бота от реальной записи.

**Сосуществование с Photon:** живой PvP **остаётся** (фазы 13–14). Продуктовое правило приоритета на экране поиска: короткое окно живой очереди → если пары нет к `MATCHMAKING_UI_TIMEOUT_SEC` (30 с), переключение на async-дуэль (чужой ghost → бот) вместо пустого экрана. Async — основной путь на старте, Photon активируется по мере роста concurrency.

## Что НЕ делаем в этой фазе

- Photon / живая синхронизация (фазы 13–14 — отдельно, сохраняются).
- Публичные профили и просмотр чужих записей вне матча.
- Подбор «по скиллу» сложнее, чем трофейный band (ML-матчмейкинг — позже).

## Предусловия

Фаза 12 (Ghost против себя: `GhostRecorder`, `GhostPlayback`, `onGhostMatchFinished`, схема `matches`/Storage). Фаза 05 (бэкенд-ядро).

## Поток

1. Каждая завершённая сессия (тренировка/дуэль) кандидат на сохранение ghost-записи в общий пул, не только как личный best.
2. На «Найти соперника»: после окна живой очереди CF/клиент берёт случайную запись из `ghost_sessions` в диапазоне `[мои трофеи ± GHOST_POOL_TROPHY_BAND]`, исключая свои.
3. Если в band нет записей → выбрать бота-пейсера, чей целевой счётчик соответствует трофейному диапазону игрока.
4. Дуэль и экран результата — те же шаблоны, что Ghost/PvP (экраны 4–6). Соперник подписан ником из записи (бот — нейтральным именем из пресета).
5. Финиш → `onGhostMatchFinished` с `mode: "async"`, ссылкой на источник (`opponentUid` для реальной записи / `botProfile` для бота), идемпотентность как в фазе 12.

## Новые константы (добавить в `constants.md`)

| Имя | Значение (предложение) | Назначение |
|-----|------------------------|-----------|
| `GHOST_POOL_TROPHY_BAND` | `150` | Полуширина диапазона подбора чужой записи по трофеям |
| `GHOST_POOL_SAMPLE_LIMIT` | `20` | Сколько кандидатов читать, прежде чем выбрать одного |
| `BOT_PACER_PROFILES` | `slow/medium/fast` | Пресеты темпа для пустого пула |

Трофеи за async-дуэль: использовать **те же `TROPHY_GHOST_WIN` / `TROPHY_GHOST_LOSS`** (12 / 7), что и для Ghost — соревнование «облегчённое» относительно живого PvP. Решение можно пересмотреть в балансе.

## Затрагиваемые экраны

Экран 2 (поиск соперника): таймаут живой очереди → async-дуэль вместо «не найдено». Экраны 4–6: те же, что Ghost/PvP, с ником/аватаром соперника из записи или пресета бота.

## Файлы

- `Assets/_Project/Scripts/Ghost/GhostPool.cs` — выбор записи из пула по трофейному band, исключение своих.
- `Assets/_Project/Scripts/Ghost/BotPacer.cs` — генерация/загрузка синтетического темпа, отдаёт кадры в `GhostPlayback`.
- `functions/src/pickGhostOpponent.js` — callable: вернуть запись/бота по диапазону игрока (читает индекс, не светит чужие профили целиком).
- Расширение `functions/src/onGhostMatchFinished.js` — ветка `mode: "async"`, поля `opponentUid` / `botProfile`.
- Индекс пула: поле `trophiesAtRecord` в `ghost_sessions` + составной индекс Firestore для выборки по диапазону.
- Storage/Firestore rules: чтение чужого `best.bin` **только** через выдачу в матче (CF-посредник), не напрямую.

## Acceptance criteria

- [ ] При пустой живой очереди игрок всегда получает соперника: чужой ghost при наличии в band, иначе бот.
- [ ] Подбор не возвращает собственную запись игрока.
- [ ] Бот неотличим в UI от реальной записи (ник из нейтрального пресета, тот же плеер).
- [ ] Трофеи начисляются по `TROPHY_GHOST_*`; запись `matches` с `mode: "async"` находится в истории профиля (`array-contains` по своему uid).
- [ ] Идемпотентность: повторный вызов `onGhostMatchFinished` не дублирует трофеи/XP.
- [ ] Чужой `best.bin` недоступен напрямую, только в рамках выданного матча.

## Тестирование

Засеять `ghost_sessions/staging` записями в разных трофейных диапазонах; проверить выборку в band и исключение своих. Очистить band → убедиться, что подключается бот. Сравнить экран результата с PvP/Ghost на консистентность.

## Связь с дизайном

Экран 2 перестаёт быть «пустой комнатой»: всегда ведёт в матч. Экраны 4–6 переиспользуются без новых макетов.
