# Фаза 00 — Репозиторий и документация

## Цель фазы

Зафиксировать структуру mono-repo (Unity позже добавится в подпапку), базовый `.gitignore`, лицензию при необходимости и убедиться, что вся документация из мастер-плана присутствует в репозитории.

## Что НЕ делаем в этой фазе

- Не создаём Unity-проект (фаза 02).
- Не подключаем Firebase/Photon SDK.
- Не пишем игровую логику.

## Предусловия

Нет.

## Затрагиваемые экраны / системы

Репозиторий целиком.

## Файлы к созданию / изменению

- `.gitignore` — Unity + Rider/VS + OS + Firebase ключи (`google-services.json` опционально через secrets).
- `LICENSE` или заглушка (если решено опенсорсить часть).
- Проверка наличия: `PROJECT_PLAN.md`, `README.md`, `docs/**`.

Рекомендуемая структура после Unity:

```
/Assets
/Packages
/ProjectSettings
/functions          ← Cloud Functions (фаза 05)
/docs
```

## Acceptance criteria

- [x] `git init` (или клон) и первый коммит с документацией.
- [x] `.gitignore` исключает `Library/`, `Temp/`, `Obj/`, `Builds/`, `.gradle`, и т.д.
- [x] В README есть ссылка на PROJECT_PLAN.md.

## Тестирование

- Клонировать репозиторий на вторую машину и убедиться, что документы читаются.

## Артефакты на выход

Коммит «docs: initial plan and architecture».

## Связь с дизайном

Нет UI.
